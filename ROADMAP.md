# Roadmap

Philosophy Lab should grow by adding real exhibits and promoting only patterns that repeatedly prove useful.

## Foundation — current

- [x] Establish the repository boundary relative to `worldview-lab` and `truth-core`.
- [x] Add the coding-agent repository foundation, environment-v1, deterministic validation, Renovate, devcontainer, and Pages delivery.
- [x] Add a dependency-light TypeScript web shell.
- [x] Add the first interactive argument exhibit with tested premise-state semantics.
- [x] Record explicit foundation-stage exceptions for theme preference, localization, and shareable state instead of silently diverging from the shared UI conventions.

## Next implementation horizon

1. **Objection and reply branches** — extend one exhibit with explicit attack/reply relationships without generalizing into a universal graph model.
2. **Paradox exhibit** — add a Ship of Theseus presentation that tests whether argument-shaped primitives are sufficient for identity puzzles.
3. **Viewpoint comparison** — present two or three positions side-by-side and record which presentation primitives repeat.
4. **Promote proven application contracts** — once multiple real exhibits exist, remove the relevant foundation exceptions by adding URL-addressable interactive state, light/dark/system theme preference, and `en`/`de`/`es` localization at stable content boundaries.
5. **Accessibility and web-quality depth** — add browser-level accessibility and lightweight web auditing once the site has enough UI surface to justify the cost.

## Deferred until evidence exists

- React or another UI framework.
- A generic graph library.
- WASM or Rust kernels.
- A universal claim/ontology schema.
- Formal proof integration with `truth-core`.
- Cross-repository worldview synchronization.

Each of these may become useful, but the trigger should be a concrete exhibit or repeated pattern rather than architectural anticipation.
